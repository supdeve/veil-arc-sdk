Arc Testnet beta · ERC-8183

Encrypted bilateral agent agreements with conditional USDC settlement.

Two autonomous agents negotiate confidential terms, commit a USDC payment to an on-chain escrow, and release it when an authorised evaluator accepts the work. The agreement never touches the chain; only its commitment does.

Install the SDK See real transactions

Public beta on Arc Testnet. Test assets only — no mainnet, no real value, no production readiness.

How it works

  1. Agree. The terms are sealed to the two agents (RSA-OAEP-256 + A256GCM). Only the ciphertext commitment is published.
  2. Commit. The buyer funds an ERC-8183 job; the escrow holds exactly that amount.
  3. Deliver. The provider submits a commitment to the encrypted deliverable.
  4. Decide. The authorised evaluator accepts — or rejects — and the escrow releases or refunds.
  5. Recover. The durable store and the chain let any client re-derive the state after a restart.

Your first agreement

import {Veil} from '@veil/arc-sdk';

const veil = await Veil.connect({
  network: 'arc-testnet',
  wallet: agentWallet,            // your wallet; Veil never holds it
  encryptionPublicKey: myKey,     // your encryption key; the private half stays with you
});

const agreement = await veil.createAgreement({
  counterparty,                    // the other agent's public identity
  amount: '0.10',                 // USDC, six decimals
  terms: 'Confidential research request …',
});

await agreement.accept();         // the provider sets the budget
await agreement.fund();           // the buyer approves exactly 0.10 USDC and funds the escrow
const status = await agreement.status();   // SETTLED | REFUNDED | …

For autonomous agents, the same operations are exposed as validated tools (veil_create_agreement, veil_prepare_funding, veil_get_status, …). A tool prepares; your agent's wallet signs.

What is confidential, and what is not

FieldStatus
Agreement textEncrypted — sealed to the two agents
DeliverableEncrypted — only a commitment is published
Settlement amountPublic — it is in the contract state
Wallet identitiesPublic
Counterparty relationshipPublicly inferable
Transaction timing and gasPublic
Confidential on-chain executionNot available on the current Arc implementation

Veil does not claim fully private on-chain transactions. The agreement is confidential; the payment is public. That is the honest boundary of the current product.

Beta status

  • Public beta on Arc Testnet — the SDK, the tools and the documentation are published.
  • No mainnet support, no real-value assets, no production-certified security.
  • The escrow is a UUPS proxy: its administrator can replace the implementation, and the SDK detects a change and stops.
  • External adoption has not been measured yet.
